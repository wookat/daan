## 2. 被拒发现与理由（8 条）

1. 「`refresh_question_stats` / 题目统计把探针与单 uid 计入 attempt_count」—— 误报：db.py 2721–2745 两条聚合 SQL 均带 `{REAL_TRAFFIC}`（`COALESCE(probe,0)=0`），R483 已回填并核 `attempt_count>=1` 911 = REAL_TRAFFIC distinct qid 911。
2. 「#640 的 400 映射已覆盖畸形 JSON 写锁问题」—— 不成立：pr640 main.py diff 仅把 OverflowError 加入 `_bad_param_handler`，未捕获 `sqlite3.ProgrammingError`，且 handler 在事件循环线程无法回滚工作线程连接；审方在 pr640 同等代码路径下复现 500 + 30 s 锁等待。
3. 「exam_api.py:476 已在 attempt 里写 question_ids 快照，只需报告侧读取」—— 误读：476 只是把 active qids 传给 `_judge_paper`；`exam_attempts` DDL 与 add_column 均无 question_ids 列，快照需新增列（已并入 W10-A）。
4. 「team/panel 单人小队仍显示成员列表与排行」—— 误报：panel.wxml 31 `wx:if="{{members.length <= 1}}"` 已渲染 kg-empty「队里还只有你一个人」，排行卡在 `wx:else` 分支内。
5. 「H5 卷库低样本文案需前端加阈值」—— 修法位置错误而非发现错误：list.vue 66 与 list.ts 77 都已按 `takers`/`avg_score != null` 条件渲染，服务端一处门控即两端生效，前端不改（并入 W10-A）。
6. 「单一 uid 主导 answer_log 说明统计失真需清洗」—— 已知且已处理：W9 #93/R374 起探针口径过滤，09-03 前流量不可分类不回填；生产只读核对 probe=0 行数个位数，不构成新缺陷。
7. 「hs 正文与答案冲突 5/1338 需批量修」—— 与 W9 #90 同一问题、命中率同量级（≈3.7‰ vs ≈0.7‰），W9-A 已加扣分规则；批量处置属 admin 人审决策，转 deferred 保留数据。
8. 「`/api/exam/papers?limit=-1` 返回 200 条证明负 limit 全表」—— 证据错配：该端点本就无 limit 参数、返回全部卷；负 limit 的有效证据是 `/api/shenlun/questions?limit=-1` 208/208（已作为 W10-A 依据）。

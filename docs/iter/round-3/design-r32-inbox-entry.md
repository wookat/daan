# R32 设计方案：讨论页消息入口（收件箱可发现性）

日期：2026-08-29 ｜ 轮次：round-3 R32 ｜ 前置：R30/R31 收件箱

## 1. 取证与差距

- 现状实查：收件箱入口只在「我的」页学习分组；讨论页（discuss.vue，用户互动发生地）无任何消息入口，被回复/点赞的用户若不去「我的」页则零感知。
- 竞品讨论社区惯例：讨论/社区页头部有消息铃铛入口+未读红点。
- P1，属 R30/R31 功能可发现性收尾。

## 2. 方案

- discuss.vue 排序 chips 行右侧（`共 n 条讨论` 旁）加「消息」入口：铃铛 icon + 未读数 badge（>0 时显示）。
- 登录态 onShow 拉 `fetchCommentInbox()` 取 unread（复用 R30 接口，失败静默）；未登录不请求、点击导登录。
- 点击跳 `/pkgA/social/inbox`；从 inbox 返回 onShow 重拉自动清 badge。
- 移动/桌面同一入口（chips 行两端对齐已有 `.cnt`，紧邻加 `.msg`）。

## 3. 不做

- 全局顶栏消息中心（uni-app 自绘 tabbar 外顶栏改造成本高，收益有限，候选后续轮）。
- 轮询/推送。

## 4. 验收

- H5 build；生产：B 回复 A 后，A 打开任意讨论页见「消息 1」badge → 点击进收件箱 → 返回讨论页 badge 消失；未登录无请求、点击导登录；1440/375 无溢出回归。

# R36 设计方案：解析区「抢首评」引导 + 讨论页输入直达（UGC 冷启动漏斗）

## 现状取证（2026-08-29）
- 生产全站仅 3 题有讨论（/api/comments/plaza 返回 3 条聚合），R33 广场/R34 热评/R35 SSR 外显把「消费端」全部打通，但「发布端」漏斗没变：解析区对无评论题只显示一行「💬 讨论 (0) ›」，零发布引导。
- 进入讨论页后还需再点输入框才能开始写——从「看完解析想吐槽」到「正在打字」要 2 跳 + 1 次聚焦。
- 竞品惯例（粉笔）：解析下方无评论时直接显示「快来发表你的看法」输入引导条，点击即达评论输入态。

## 差距定级
P1（功能深度/UGC 冷启动）：讨论体系消费端完备但发布转化路径弱，内容池增长慢。

## 方案
1. `q-social-bar.vue`：`count === 0` 时在链接行下方渲染「抢首评」引导条（伪输入框样式：「这题还没有讨论，说说你的解法，抢首评 →"），点击 `openDiscuss(true)` 跳 `discuss?qid=&focus=1`；`count > 0` 保持 R34 热评卡不变。
2. `discuss.vue`：`onLoad` 读 `opts.focus`，登录态时给 `<input>` 绑定 `:focus="autoFocus"` 自动聚焦（未登录不聚焦，点输入框仍走 ensureLogin 登录引导）。

## 不做
- 解析区内嵌真实输入框直接发评（保持讨论页为唯一发布场，避免解析区状态复杂化）；
- 已有评论题增加发布引导（热评卡本身即入口）。

## 验收
- 本地 H5 build 通过；
- 生产：无评论题解析区显示引导条、点击直落讨论页且（登录态）输入框已聚焦；有评论题仍显示热评卡无引导条；游客点击引导条落讨论页不聚焦、点输入框走登录引导；1440/375 无溢出、console 0 error；R34/R35 回归。

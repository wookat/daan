# R154：搜索历史——闲置态从纯文案提示变成可点的再搜索入口

## 取证（2026-08-29）

- 现状（源码 + 生产实查）：搜索页闲置态只有一行静态文案「支持搜索：题号语义码、
  题干关键词、考点名、试卷名」，全仓无任何搜索历史实现（`grep 历史/history`
  0 命中）；用户每次进入搜索页都要重新手动输入上次的关键词。
- 竞品参照：主流刷题/搜索产品（夸克搜索、粉笔搜索）闲置态均提供「搜索历史」
  chips 一键重搜（基于此前竞品取证轮的通用模式；本轮未重新逐像素取证，
  按行业惯例与既有取证记忆立项）。
- 搜索是 R152/R153 连续两轮投入的 golden path，闲置态是该路径的第一屏。

## 方案

- 本地 `kgSearchHist`（uni storage，≤10 条，去重前插，无后端无隐私上报）。
- 仅在「无结果、无错误、非 loading」的闲置态渲染「搜索历史」区块：
  chips 一键回填关键词并搜索 + 「清空」按钮（role=button + aria-label）。
- 成功返回结果（含空结果）才记入历史；失败不记。
- 零后端改动。

## 验收

- 生产 1440/375：搜两个词→清空输入→历史 chips 出现→点 chip 原词重搜出结果
  →点清空→区块消失；溢出 0、console 0 error。

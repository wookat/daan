# R33 设计方案：讨论广场（热议聚合页）

日期：2026-08-29 ｜ 轮次：round-3 R33 ｜ 前置：R25 讨论页桌面化、R30–R32 收件箱闭环

## 1. 取证与差距

- 现状实查（代码+生产）：讨论完全按题分散，入口仅三处——题目社交栏（q-social-bar）、收藏页、收件箱条目跳转；全站无任何「哪些题正在被讨论」的聚合曝光面，用户不刷到具体题就永远看不到 UGC。
- 竞品惯例：粉笔每题解析页外显热门评论、并有社区热议流；讨论内容的聚合曝光是带动 UGC 参与的标准做法。
- P1：R28–R32 已补齐发布/治理/通知闭环，聚合曝光是讨论功能深度的下一块短板。

## 2. 方案

### 后端（social.py，只读接口）

- `GET /api/comments/plaza?limit=20`（无需登录）：
  - 按 `question_id` 聚合 `question_comments WHERE status='ok'`：讨论数 cnt、最近活跃 `MAX(created_at)`，按最近活跃倒序取 limit（上限 50）；
  - 每题附最新一条 ok 评论（昵称+正文）与题干摘要（`questions.question` 截 80 字 + module）；
  - 返回 `{items:[{question_id, stem, module, cnt, last_at, latest:{nickname, content}}]}`。

### 前端

- 新页 `pkgA/social/plaza.vue`「讨论广场」：卡片流（题干摘要+模块 chip+讨论数+最新评论一行），点击跳 `/pkgA/social/discuss?qid=`；空态引导去刷题区发评论。游客可看（只读），发言仍在讨论页内走登录。
- 入口：首页「更多练习」grid 增一卡「讨论广场」（messages-square icon，副题「考友热议 · 每题讨论」）。
- 响应式：≤768 单列（复用 inbox 卡片语言）；≥1024 两列网格。

## 3. 不做

- 独立发帖社区（脱离题目的自由帖）——超出错题工具定位，候选远期。
- 广场内直接回复/点赞（保持讨论页为唯一互动场，避免双入口状态同步复杂度）。

## 4. 验收

- py_compile + ruff（不新增错误）+ H5 build；
- 生产：广场列出有讨论的题（含 R25 历史评论），卡片信息完整、点击跳对应讨论页；游客可浏览；1440 两列 console 0 error；375 单列无溢出；讨论/收件箱回归。

# R153：搜索页失败态收口——失败不再伪装成闲置提示

## 生产取证（2026-08-29，abort 探针，1440）

- 拦截 `/api/search` 后在生产搜索页搜「隧道」：toast `request:fail` 约 1.5s
  消失，页面回落到闲置提示「支持搜索：题号语义码、题干关键词、考点名、试卷名」，
  与从未搜索过的状态无法区分——R134–R137 系列同类缺陷（失败伪装成非失败态）
  在搜索页的遗漏面。
- `loadMore`（加载更多）与 `toggleDetail`（展开详情）失败同样仅 toast，无驻留反馈。

## 方案（对齐 R134 既有「加载失败 + 重试 ›」模式）

- `doSearch` catch 置 `loadErr`，模板在 loading/result 之外渲染驻留错误卡
  「加载失败 + 重试 ›」，重试即重跑 `doSearch`；成功清除。
- 失败时不清空上一次成功结果之外的状态语义：`result=null` 时才落错误卡；
  已有结果时保持结果 + toast（避免打断浏览中的列表）。
- `loadMore` 失败保持 toast（列表仍在，可再点「加载更多」重试，语义自洽）。
- 零后端改动。

## 验收

- 生产 abort 探针：失败后出驻留错误卡；放行后点「重试 ›」原位恢复结果。
- 1440/375 双视口、溢出 0、console 0 error。

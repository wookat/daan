# R204：SSR 分页导航补页码窗口（首/±2/末 直达）

## 取证（2026-09-01，生产一手）

- SSR 分页页族（模块 hub/子题型/考点/年份，共用 `_pager()`）当前只输出
  首页/上一页/「N / 总页数」/下一页/末页——无任何页码直达链接。
  实测 /tiku/panduan/ 共 459 页，从入口到第 50 页需 ~49 次连续「下一页」跳转；
  非探针 origin 日志 24h 内实见爬虫在磨 /tiku/panduan/?page=254 深页
  （链接深度 ~250 或从末页反向 ~200 跳），深页发现效率与权重传递差。
- 用户侧同理：落在中间页无法跳转到附近页，只能逐页翻。
- 既有语义已正确的部分保持不动：page=1 canonical 到干净路径、
  rel=prev/next、超范围 noindex 404、每页唯一 title/description。

## 方案

`_pager()` 改为页码窗口（对 4 个调用方零改动）：

```
上一页 | 1 … (page-2 … page+2, 当前页 <span aria-current="page">) … 末页码 | 下一页
```

- 窗口 = 当前页 ±2；与首/末页不相邻时以 … 间隔；page==1 链接用 base_path（无 ?page=1）。
- 保留 rel=prev/next；删除原「N / pages」纯文本（当前页页码即位置指示）。
- 深页链接深度从 O(n) 降为 ~n/5 且任意页与首末页/邻近 5 页一跳互达。

## 验证计划

- pytest 新增：中间页窗口/省略号/aria-current、首尾页边界、page=1 无 ?page=1 链接。
- ruff/pytest 全绿 → 部署 → 生产 1440/375 分页页溢出 0、console 0 error、
  R196 性能预算全过。

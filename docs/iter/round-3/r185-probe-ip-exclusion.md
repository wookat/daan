# R185：周报探针流量剔除（--exclude-ip-file）

## 取证

R184 切到 origin 日志后首份周报（2026-09-01 手动触发）显示：总请求 82889，
其中「疑似真人 77836」「404 70050」「502 2845」——按 R183 的 X-Kg-Ip 逐行归因，
这些几乎全部来自本会话探针 IP（140.232.64.5，R181 风暴复现/双视口复验/curl 自测）。
即：不剔除探针，周报的「真人流量」「错误率」两个核心口径都会被开发活动淹没，
违背「不造假数据/不把探针当真实用户」的口径要求。UA 无法区分（探针用真实 Chrome），
IP 是唯一可靠维度。

## 方案

1. `scripts/access_log_report.py` 新增 `--exclude-ip-file PATH`：逐行 IP（# 注释），
   按 `X-Kg-Ip[0]`（回退 `remote_ip`）匹配剔除；剔除量单独计数并在报告头外显
   （「探针流量已剔除: N」），保证口径透明可审计，文件缺失时静默等同不剔除。
2. `deploy/cron_access_report.sh` 两条统计路径均传
   `--exclude-ip-file /home/ubuntu/kaogong-reports/probe-ips.txt`。
3. 服务器建 `probe-ips.txt`（首条为本会话出口 IP 140.232.64.5）。
4. SOP：后续开发会话在做生产探测前，把 `curl -s https://api.ipify.org` 结果
   追加到该文件（带日期注释），会话出口 IP 变化时同步更新。

局限（如实声明）：剔除只按 IP，若未来探针 IP 未登记则仍会混入；清单只影响
周报统计口径，不影响原始日志与归档（可随时全量复算）。

## 验证

- 服务器实跑：无清单时输出与 R184 基线一致；建清单后周报头出现
  「探针流量已剔除: 8xxxx」，剩余统计与 R183 非探针归因口径吻合
  （少量真实爬虫/回源请求 + 预期 403）。

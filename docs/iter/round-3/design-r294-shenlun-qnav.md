# R294 设计：申论详情页「上一题/下一题」连看导航（含收藏视图 + 桌面 ←/→）

## 取证（verified，一手源码/生产实查）

- 申论详情页（作答页）唯一出口是「‹ 返回列表」：想连看多题必须 详情→返回→滚动定位→再点开，N 题连看需 2N 次往返；列表滚动位置在切详情后无锚点保持。
- 成绩报告解析浮层 R290 已建立「上一题/下一题 + 桌面 ←/→」先例（qNavState 同型纯函数 + INPUT/TEXTAREA 焦点守卫），行测侧闭环，申论侧缺同能力。
- R293 收藏视图（qFavOnly + qFavs 快照）上线后，「连看我收藏的几道题」是收藏视图的自然后续动作，当前同样每题都要往返列表。
- 对标粉笔：申论题目详情页有上下题切换。

## 方案（纯前端，零后端/零契约变化）

- 纯函数 `src/shenlun-qnav.js`：`qNavState(ids, curId)` → `{ idx, total, prevId, nextId }`；不在列表（深链直达 ?id 不在当前 20 条内）时 idx=-1 不渲染导航，边界返回 0。
- 详情卡尾部导航行：`‹ 上一题 | i/N | 下一题 ›`，在当前列表上下文 `shownQs`（普通列表或收藏视图）内步进，复用 `openQ`（草稿/历史/批改状态按既有逻辑逐题重置）；边界 aria-disabled 置灰。
- H5 桌面 ←/→ 键切题：window keydown（onShow 挂/onHide/onUnload 卸，对齐 report.vue R290），守卫 INPUT/TEXTAREA/SELECT/contentEditable 焦点与修饰键——作答 textarea 内左右键完全不受影响。
- total>1 才渲染；单题/空列表/深链不在列表均不渲染。

## 不做

- 不改 openQ 数据链路、草稿、批改、历史；不改 URL 语义（连看切题沿用既有 ?id 行为？——openQ 本身不写 URL，本轮不新增，保持现状）；不加载更多自动翻页（到列表尾即禁用）。

## 验证

- vitest：qNavState 中间/首/末/单题/不在列表/空列表。
- 生产 1440/375：列表进详情导航就位、下一题切题、收藏视图内连看只在收藏集内步进、textarea 内左右键不切题、溢出 0、console 0 error、性能预算。

# R34 设计方案：解析区热评外显（q-social-bar 内嵌热门评论）

## 现状取证（2026-08-29）
- 刷题/错题本/搜索等所有解析区通过 `q-social-bar` 暴露讨论入口，但仅为一行「💬 讨论 (n) ›」计数链接（q-social-bar.vue L24），UGC 内容零外显。
- 已有讨论内容（R25/R28 起真实评论），生产 `GET /api/comments?question_id=&sort=hot` 游客可访问，返回按赞数排序的 ok 评论。
- 竞品惯例（粉笔/夸克刷题）：题目解析下方直接外显 1–2 条热门评论（昵称+内容+赞数），点击进入完整评论区——评论是解析的补充学习材料，外显能显著提升 UGC 消费与发布动机。

## 差距定级
P1（功能深度）：讨论数据已存在但在题目现场不可见，用户须主动点击才能发现讨论价值，与竞品「热评即解析补充」体验差距明显。

## 方案
仅改 `frontend-uni/src/components/q-social-bar/q-social-bar.vue`（组件级改动自动惠及刷题页、错题本、搜索等全部引用位）：

- `load()` 中当 `count > 0` 时追加拉取 `fetchComments(qid, 'hot')`，取 `items[0]`（含其点赞数）存 `hot`；
- 「讨论」行下方渲染热评卡：`🔥 热评`标签 + 昵称 + 内容（两行截断）+ 👍 赞数；点击整卡 `openDiscuss()`；
- 切题（watch questionId）时清空 `hot`；接口失败静默（非关键路径）；
- 无热评（count=0）零变化；无新增依赖、无后端改动。

## 不做
- 解析区内直接点赞/回复（保持讨论页为唯一互动场）；
- 展示多条热评（v1 一条，避免解析区膨胀）。

## 验收
- 本地 H5 build 通过；
- 生产：有评论题解析区可见热评卡且点击跳讨论页、无评论题零变化；1440/375 无溢出、console 0 error；讨论页/广场回归。

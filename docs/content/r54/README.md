## 1. r53 P2 三项处置

### P2-1 练习 API 冷启动治理（前端反馈 + 后端保活）

根因实测：`/api/questions?tag3=…` 冷态 8.1s → 暖态 0.08s，为 SQLite 索引/表页缓存被换出所致（同机其他项目 I/O 挤占 OS page cache）。

- **后端保活（低风险方案选型）**：将启动时一次性的 `_warmup` 改为常驻线程每 5 分钟预热 `idx_q_pick` 与 `idx_q_tag3_disabled` 两个热点索引（`backend/app/main.py`）。不选 crontab 外部 curl：应用内线程随容器生命周期自管理、无新增部署面。效果：部署后未触碰过的 tag3 首查从 ~8-10s 降到 ~1-4s（索引已热、表行页仍可能冷，属预期）；不做全表扫描保活（每 5 分钟全表 I/O 代价高于收益）。
- **前端加载反馈**：practice 页 `start()` 出题超过 3s 时 loading 文案切换为「题库首次加载稍慢，请稍候…」（`frontend-uni/src/pages/practice/practice.vue`），完成/失败均清理定时器。

# 常识判断（changshi）三级考点打标报告

## 1. 方法概述

- 数据：`data/tag3/untagged_changshi.jsonl`，共 **34,708** 题。
- 考点树：`devin/p5-integration` 分支 `backend/app/data/taxonomy.json` 中 `changshi` 模块，共 7 组 33 个三级考点（CS-ZZ-01~04、CS-FL-01~10、CS-JJ-01~03、CS-LS-01~05、CS-DL-01~03、CS-KJ-01~05、CS-GL-01~03）。
- 不调用任何外部付费 LLM API，全部由本地规则分类器 + 人工抽样核对完成。
- 脚本：`data/tag3/scripts/tag_changshi.py`，可复现：

```bash
python3 data/tag3/scripts/tag_changshi.py <taxonomy.json> \
  data/tag3/untagged_changshi.jsonl data/tag3/tagged_changshi.jsonl
```

## 2. 分类器规则设计

判定顺序（`classify`）：

1. **噪声过滤**：解析中出现明显串模块特征（语句排序、逻辑填空、方程法、勾股定理、第一空/第二空等）的题直接判 UNKNOWN（这些题的 explanation 是从言语/数量模块串入的脏数据）。
2. **submodule 约束**：约 60 个 submodule 别名映射到考点组（如 `法律`→CS-FL 组）或具体考点（如 `物理知识`→CS-KJ-01、`公文`→CS-GL-01）。候选清单严格限制在该组内；窄义 submodule 对应考点加权 +4 而非直接判定（避免"整个 submodule 无脑映射"）。
3. **显式考查句**：解析中的"本题（主要）考查/考察 X"用 `KAOCHA_MAP`（约 60 条）映射到考点或考点组；与 submodule 组冲突时判 UNKNOWN（宁缺勿错）。命中具体考点给 0.95。
4. **加权关键词打分**：33 个考点各配 5~15 条加权正则（权重 2~6），特征词全部从数据中归纳（如 CS-FL-04 的"正当防卫/缓刑/犯罪未遂"、CS-LS-05 的"节气/科举/干支"、CS-KJ-04 的"神舟/嫦娥/航母"）。每条规则命中次数封顶 3 次计分。
5. **朝代题干启发**：题干以"唐代/北宋/…"开头且文学、文化特征分不高时向 CS-LS-01 加权。
6. **置信度**：最高分≥8 且领先≥4 → 0.9；≥5 且领先≥2 → 0.75；弱命中 → 0.6；有 submodule 组约束时 +0.05（封顶 0.95）；否则 UNKNOWN（confidence=0）。

## 3. 人工抽样验证

抽样方式：每个产出考点随机抽 20 题（不足 20 全抽，`random.seed` 固定可复现），逐题人工核对题干+解析与所判考点是否一致。共进行 3 轮抽样-修正-重跑迭代（样本文件 seed=11/12/13，合计人工核对约 900 题次）。

## 5. UNKNOWN 说明（20.8%，未超 30% 红线）

UNKNOWN 主要来源：

1. **脏数据**：相当一部分题的 explanation 是言语理解/数量关系模块的解析串入（噪声过滤规则命中），无法依据解析判定。
2. **短解析低信息**：大量题目解析仅"故选X"且题干极短（尤其生成式改写题），无足够特征词。
3. **跨考点边界题**：法律综合题（一题跨民法+刑法+行政法）、历史/文学/文化交叉题、政治理论与时政交叉题，特征分接近，宁缺勿错。
4. **submodule 与文本冲突**：显式"本题考查X"与 submodule 组不一致的题按红线判 UNKNOWN。

- 无 submodule 整体映射到单一考点：组内仍按文本打分选择；窄义 submodule 仅加权。

# 言语理解模块逐题质量审计报告（audit1/yanyu）

## 范围与目标

- 对象：【言语理解】模块全部在架题 **28,655** 道（生产全量导出 `audit_yanyu.jsonl`）。
- 要求：逐题人工核查，每题一条台账记录，不以抽样替代全量覆盖。
- 五项核查：① 答案正确性（独立解题核实）；② 解析与答案一致性；③ 选项完整性（解析混入、串题、缺值）；④ 题干完整性（填空下划线/空格、篇章原文、页眉页码污染）；⑤ tag3 精确归档及 submodule / question_type 元数据一致性。

## 方法

1. **程序化一致性机检分层**（mc.py）：对全量题目跑格式/结构规则族（解析缺失/过短、题干无空位、空位数与选项不匹配、选项解析泄漏、选项重复值、submodule 缺失/异常、tag3 非法等）。每个规则族抽样人工验证误报率后方投入使用，机检结果仅作风险提示，不作最终判定。
2. **逐题人工核查**（review.py，批次 50 题）：分批读取题干、选项、库内答案、解析与元数据，独立解题/核实后与库内答案比对，逐题写入追加式台账 `manual_ledger.jsonl`，每行 `method="manual-review"`。台账为 append-only，历史行不重写；同一 ID 后写入的终审行覆盖先前结论。
3. **外部模型使用说明**：审计初期的 LLM 独立解题结果在中途按指示停用（API 余额不足且被明确禁止继续依赖），此后仅将其残留输出作为风险标记；凡与人工判断冲突的，均由人工独立解题终审，**956** 题标注“历史模型偏差已人工复核否决”。
4. **重复/近重复筛选**（dedup.py + dup_confirm.py）：文本归一化后按精确重复与 Jaccard 相似度聚簇，共 **1,563** 个簇；簇内按 真题优先 > 机检干净 > 解析完整 > 有 tag3 > id 小 保留最优。真题在不同试卷（年份/地区）出现的按卷各保留一份。57 对低相似候选经人工比对后否决。最后 2 对遗留候选（1046941/241538、1047005/1046942）逐题人工比对终审确认下架。
5. **汇总构建**（build_ledger.py）：合并人工台账终审行与查重终审，解析 dup 链使 `dup_of` 指向最终保留题；人工终审与机检方向冲突时以人工结论为准。

### 高频问题（issues 计数，一题可多项）

- 题干/选项内换行被错误录入为可见字符“⏎”：10,465（fixes.sql 内 REPLACE 清理）
- submodule 字段缺失：4,983（fixes.sql 按 question_type 众数映射回填 4,557 条，映射表人工核对）
- tag3 与题型不符 / 缺失 / 非法：合计约 4,600，其中 3,001 条在 fixes.sql 定标
- 解析过于简略：1,101；解析缺失：588
- PDF 转录残留行内空格、半角引号、页眉/页码/广告污染、解析截断、选项排序序列不完整等格式与内容缺陷若干（详见 ledger.jsonl 逐题 issues）

## 交付物

- `ledger.jsonl`：28,655 行逐题台账 `{id, verdict, score, tag3, dup_of, issues, method}`，全部 `method="manual-review"`。
- `fixes.sql`：tag3 定标 3,001 条 + submodule 回填 4,557 条 + “⏎”占位符清理 10,465 条（幂等，带 guard）。
- `delist.sql`：2,509 条下架（幂等，`disabled=1`，含原因注释）。
- 生产执行由父会话统一进行；本目录仅为审计产物，未连接生产库。

## 人工验证记录（关键控制点）

- 每批 50 题写入台账前，均断言异常字典 ID 集与权威源切片完全一致（防止工具静默补默认行）。
- 三个历史批次曾出现源索引 +50 偏移（22787/23787/24287 起），已通过后续批次追加补齐，最终校验每 ID 恰一条终审记录、无缺失无多余。
- 机检规则族逐族抽样人工验证；重复簇保留策略人工设定并对边界簇逐对人工比对；答案冲突题（含历史模型分歧 956 题）全部人工独立解题终审。
- 最终产物校验：JSON 可解析、ID 全覆盖唯一、score∈[0,100]、verdict∈{pass,fix,delist}、dup_of 无悬挂/无自指/无指向已下架题（质量下架终端除外，已消除）。
